# 暗号化バックアップ・復元

Bot 本体とは別に、運用者が明示的に起動する復旧用ヘルパーです。指定した `.env` と Bot 専用の `auth.json` だけを読み、暗号化します。Bot の起動、設定の上書き、ログイン、Library への通信は行いません。

- 初回から自動バックアップを使う: [v3 セットアップ](AUTOMATIC-BACKUP.md#初回セットアップv3)
- 既存の v2 バックアップから移行する: [移行手順](AUTOMATIC-BACKUP.md#既存-v2-からの移行)
- v2 / v3 を復元する: [復元手順](#復元v2--v3)

## 必要なもの・依存のインストール

- Linux と、`renameat2(RENAME_NOREPLACE)` を利用できる libc・カーネル・ファイルシステム。既存の保存先を置換しないために必要です。未対応環境では安全性を緩めず失敗します
- Python 3 と [requirements.txt](requirements.txt) の `cryptography`
- フォーム用の GTK 3 / PyGObject（Python の `gi`）と、操作できる Linux デスクトップセッション
- 本人が管理する専用の保存先と、復旧用パスワードの安全な控え

Debian / Ubuntu 系の例です。OS パッケージの導入は管理者が行い、Python 環境は Bot の Node.js 依存とは別に用意します。リポジトリのルートから実行してください。

```bash
sudo apt-get install python3-venv python3-gi gir1.2-gtk-3.0
/usr/bin/python3 -m venv --system-site-packages .venv-recovery
.venv-recovery/bin/python -m pip install -r tools/recovery/requirements.txt
.venv-recovery/bin/python -c 'import cryptography, gi; gi.require_version("Gtk", "3.0"); from gi.repository import Gtk'
```

以下の例は、この仮想環境とリポジトリルートを使用します。別の環境では、`cryptography` と `gi` の両方を読み込める Python に置き換えてください。依存の読み込み成功だけでは GUI 表示や `renameat2` の動作確認にはなりません。

## 入力・保存先の注意

- パスは絶対パスで指定します。ファイルとパス中のディレクトリの symlink は拒否されるため、`.env` がリンクなら実ファイルのパスを指定します
- 入力は実行ユーザー所有の通常ファイルで、ハードリンクのないものに限ります。上限は `.env` が 128 KiB、`auth.json` が 1 MiB、暗号化ファイルが 3 MiB です
- 出力先の親は実行ユーザー所有で、他のユーザーが書き込めない場所にします。出力名は未使用にしてください。生成ディレクトリは `0700`、ファイルは `0600` です
- 自動バックアップでは `.env` と専用 `auth.json` の両方が必須です。手動 v2 バックアップでは `auth.json` を省略できます
- 通常のコーディング用 Codex home や無関係な認証情報を選ばないでください。バックアップ・復元した認証の利用は、そのアカウントと環境で許可された範囲に限ります
- パスワードはフォームの伏せ字欄に本人が入力します。16〜1024文字の固有の長いパスフレーズを安全に控えてください。コマンド引数・環境変数・設定 JSON・ログ・チャットには入れません。紛失したパスワードは回収できません

## 復元（v2 / v3）

```bash
.venv-recovery/bin/python tools/recovery/recovery_gui.py
```

1. 「復元」タブで、手元に取得済みの暗号化バックアップと、まだ存在しない復元フォルダの絶対パスを指定します
2. 本人が復旧用パスワードを1回入力し、「復元する」を押します。v2 / v3 は自動判別されます。v3 も暗号化ファイルとパスワードで復元でき、元の watcher の状態ディレクトリは不要です
3. 成功すると新しいフォルダに `.env` と、含まれる場合は `codex/auth.json` が保存されます。既存設定は上書きせず、Bot は起動しません
4. 復元先の権限、`.env` 内の絶対パス、専用環境との対応を確認します。必要な設定反映・起動は別途行い、認証切れなら本人が再ログインします。暗号化ファイルを復元できても、サービス側で認証が有効とは限りません

復号と内容検証が完了する前に、復元ファイルを書き出しません。パスワード違い・破損・未対応形式は失敗として扱います。ディスクへの確定保存を確認できない警告や、途中の非公開一時フォルダが残るエラーが出た場合は、成功とみなさずローカルで確認してください。

Library から取得する場合は、承認された同じ保存先の履歴・受領記録を照合し、対応する Library 機能で暗号化ファイルをダウンロードしてから開きます。古い版や別のバックアップを誤って選ばないでください。

## 手動バックアップ（v2、必要な場合のみ）

同じフォームの「バックアップ」タブで `.env`、任意の専用 `auth.json`、未使用の暗号化ファイル名を指定します。Bot と対象ファイルを書き換える処理を停止してから、本人が新しいパスワードと確認を入力し「暗号化して保存」を押します。この操作はローカルに v2 を作るだけで、Library には送信しません。自動バックアップの初期設定に、この手順は不要です。

## 検証

```bash
.venv-recovery/bin/python -m unittest discover -s tools/recovery -p 'test_*.py'
```

テストは合成データと一時ディレクトリを使います。実際の `.env`、認証、Library アカウントは不要です。GUI の入力検証テストは実際の画面操作を代替しないため、デスクトップでの表示確認には `recovery_gui.py --dummy-ui` を使えます。本物の秘密情報は入力しないでください。

暗号化は秘密情報の漏えいリスクを減らしますが、保存先の保護や復元確認の代わりにはなりません。自動保存・稼働監視・容量制限は [自動バックアップ運用](AUTOMATIC-BACKUP.md) を確認してください。
